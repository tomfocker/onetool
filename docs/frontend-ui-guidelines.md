# OneTool 工具页 UI 规范

本文档用于约束 OneTool 后续工具页开发。屏幕录制页是当前基准：界面应像高频桌面工具，而不是营销页或展示页。优先保证扫读清晰、操作直接、状态明确。

## 适用范围

- 适用于 `src/renderer/src/tools/` 下的工具页面。
- 适用于面向桌面效率、系统维护、文件处理、录屏截图、下载整理等操作型功能。
- 官网、发布页、强视觉展示页可以另行设计，但不能反向影响工具页密度和控件规范。

## 核心原则

- 第一屏必须是可用工具本身，不做落地页、功能介绍页或大段说明。
- 页面只突出一个主任务：用户进来后应能立刻判断“调哪里、看哪里、按哪里执行”。
- 控件分组按工作流排布，不按实现模块堆叠。
- 文案服务操作，不解释界面。能用标签、状态、按钮表达的，不加说明段落。
- 视觉上使用中性底色加单一强调色，避免渐变标题、装饰光斑、过量阴影和大面积单色主题。

## 页面结构

工具页默认采用紧凑工作台布局：

```text
顶部状态栏
  标题 / 当前状态 / 当前目标 / 输出摘要

主工作区
  左侧：设置区
    主要对象选择
    输出/参数设置
    轻量校验提示

  右侧：操作台
    状态
    主按钮
    关键摘要
    辅助动作
```

推荐实现：

- 容器：`max-w-6xl mx-auto px-5 py-5 sm:px-6`。
- 主栅格：`grid grid-cols-1 gap-4 xl:grid-cols-[minmax(0,1fr)_320px]`。
- 右侧操作台在宽屏可 `sticky top-5`，窄屏自然下移。
- 页面区块间距优先使用 `gap-4` 或 `space-y-4`，避免大段空白。
- 不把多个大卡片纵向堆成“表单长卷”。设置区和操作区要有明显职责区分。

## 区块与卡片

- 大区块圆角控制在 `rounded-[1.25rem]` 左右，只有弹窗或特殊预览容器可以更大。
- 卡片只用于承载明确的一组控件、任务列表项或操作台，不把卡片再套进卡片。
- 常规工具页避免 `rounded-3xl`、过重 `shadow-2xl`、大面积玻璃拟态堆叠。
- 推荐区块样式基调：

```tsx
className="rounded-[1.25rem] border border-zinc-200/80 bg-white/75 p-4 shadow-[0_24px_70px_-48px_rgba(15,23,42,0.45)] dark:border-zinc-800 dark:bg-zinc-900/60"
```

## 控件规范

### 主操作

- 每个工具页最多一个主按钮，放在右侧操作台或固定操作区。
- 主按钮高度优先 `h-14`，文字使用 `text-lg font-semibold`。
- 主按钮负责执行/停止/保存这类核心动作，不和设置按钮混在一起。
- 主按钮必须覆盖禁用、执行中、错误后可重试等状态。

### 分段控件

用于二选一、三选一的模式切换，例如全屏/区域、MP4/GIF、质量等级。

- 外层：`grid ... rounded-xl bg-zinc-100 p-1 dark:bg-white/8`。
- 内层按钮：`h-10 rounded-lg text-sm font-semibold`。
- 当前选中项使用白底、轻阴影和强调色文字。
- 不给每个选项加长说明；说明应由标签、状态或必要提示承担。

### 输入、选择和路径

- 标签在上，控件在下。
- 常用控件高度统一为 `h-10` 或 `h-11`。
- 文件路径不要做成视觉很重的灰色长输入框；优先使用轻量信息行加“更改”按钮。
- 长路径、窗口名、文件名必须 `truncate`，避免撑开布局。

### 图标按钮

- 使用 `lucide-react`，不要手写临时 SVG，除非该图标库没有合适图标。
- 图标按钮需要 `title` 和 `aria-label`。
- 常用尺寸：`h-9 w-9`。

## 文案规范

- 标题短：例如“范围”“输出”“操作台”“热键”。
- 状态短：例如“待开始”“框选中”“可开始”“录制中”“保存中”。
- 按钮短：例如“开始录制”“停止录制”“框选区域”“更改”“保存”。
- 避免教程式说明，例如“点击某按钮后会如何如何”“虚线框会保留在屏幕实际位置”。
- 空状态、错误、校验信息可以出现，但必须贴近相关控件，不做独立说明卡。

## 颜色与视觉层级

- 工具页使用中性灰白/深灰底色，单一强调色用于选中、主按钮、关键状态。
- 同一页面不要混用多个高饱和强调色。
- 禁止用渐变文字、背景光斑、装饰性模糊圆点来制造层级。
- 状态色只在必要处使用：
  - 危险/录制/停止：红色。
  - 保存中/等待：琥珀色。
  - 成功完成：绿色，仅用于 toast 或完成反馈。

## 状态呈现

每个工具页至少覆盖这些状态：

- 初始状态：能直接开始主要流程。
- 进行中状态：主按钮和状态标签同步变化。
- 禁用状态：控件不可操作时必须降透明并显示禁用光标。
- 空状态：任务列表、结果列表为空时用一行轻量提示。
- 错误/校验状态：显示在对应控件附近，不放到页面顶部打断用户。

## 响应式

- 默认单列，`xl` 以上再切到“设置 + 操作台”双列。
- 所有固定格式元素要有稳定尺寸：按钮、分段控件、缩略图、任务项都不能因为 hover 或文字变化导致布局跳动。
- 宽屏右侧操作台固定宽度建议 `320px`。
- 窄屏下操作台下移，主按钮仍保持完整可见，文字不得溢出。

## 测试与验收

对明显影响体验的布局决策，应补源码约束测试，防止后续回退。例如屏幕录制页使用：

- `recorder-layout-grid` 锁定“设置 + 操作台”布局。
- `recorder-segmented-control` 锁定模式/格式/质量的分段控件。
- `recorder-action-panel` 锁定主操作聚合区。
- 同时断言旧文案、旧大卡片和旧分散布局不再出现。

提交前检查：

- 文案是否能再短一层。
- 主按钮是否唯一且位置稳定。
- 设置项是否按用户流程排列。
- 路径、文件名、窗口名是否有截断处理。
- 深色/浅色模式是否都有可读对比。
- `npm run typecheck` 和相关测试是否通过。

## 后续开发约定

- 新工具页优先复用本文的布局骨架。
- 如果功能天然需要不同布局，先说明为什么偏离，再保证控件、文案、状态和响应式规则仍一致。
- 大幅 UI 调整后，应启动本地预览并检查桌面宽屏与窄屏两种尺寸。
