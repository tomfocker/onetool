# 打印共享修复设计

## 背景

“疑难修复”板块承载可诊断、可解释、可一键执行的 Windows 修复向导。打印问题第一版聚焦“客户端连不上共享打印机”，而不是泛化成所有打印故障。用户只在客户机输入服务端 IP/主机名，OneTool 尽量从客户机判断问题更像发生在客户端、服务端、网络协议层还是凭据/兼容层。默认体验必须是“下一步该点什么”的傻瓜式向导，而不是把可能原因平铺给用户自行判断。

参考方向来自用户博客《一文速通 win11 打印共享》：主机端共享设置、客户端访问 `\\主机IP`、SMB 1.0 兜底、凭据管理、RPC 身份验证修复，以及家庭版组策略能力缺失时的处理路径。

## 目标

- 在客户机上完成主要诊断，默认不要求两台电脑都运行 OneTool。
- 将结论归类为：客户端本机问题、疑似服务端共享问题、网络/端口问题、凭据冲突/缺失、Win11 兼容问题、未知混合问题。
- 默认只暴露一个主按钮和一个下一步动作；高级诊断保留链路细节，给懂的人查看当前进行到哪一步。
- 对低风险客户端问题提供一键修复。
- 对服务端问题给出清晰检查项，不伪装成客户机可以直接修好服务端。
- 高风险兼容项必须显式确认，并清楚提示影响。

## 非目标

- 不自动替换 DLL，不做 PrintNightmare 历史补丁类“替换大法”。
- 不自动卸载或替换打印驱动。
- 不默认开启 SMB 1.0；第一版只检测和提示，后续可作为高风险兜底项加入。
- 不尝试远程修改服务端，除非后续单独做“服务端脚本生成/远程管理凭据”能力。

## 用户流程

### 客户端诊断

用户输入 `192.168.6.7`、`主机名` 或 `\\192.168.6.7\打印机名`。工具自动规范化为服务端地址和可选打印机路径。

检测项：

- 本机 Print Spooler 服务状态。
- 本机打印队列目录是否堆积任务。
- 主机是否能 ping 通。
- 服务端 SMB 445 是否可达。
- 服务端 RPC 135 是否可达。
- `\\服务端` 是否可访问。
- 本机是否已有指向该服务端的网络打印机连接。
- 是否配置了 Win11 打印 RPC 兼容注册表项。
- 是否存在 `RpcAuthnLevelPrivacyEnabled=0` 兼容项。
- 是否能读取 SMB 1.0 客户端功能状态。

输出结果：

- 一句话结论，例如“更像是服务端共享/防火墙问题”。
- 一个下一步动作，例如“保存凭据并测试”“清除旧连接”“应用 RPC 兼容修复”。
- 默认折叠的高级诊断列表，标记客户端、服务端、网络、协议/凭据。
- 推荐动作列表供高级用户直接执行。

### 修复动作

第一版提供这些动作：

- 重启本机打印服务。
- 清空本机打印队列并重启服务，执行前确认，会取消待打印任务。
- 应用 Win11 共享打印 RPC 兼容修复，执行前确认，会写入注册表并重启打印服务。
- 输入服务端账号密码后写入 Windows 凭据管理器，并重新测试 `\\服务端`；OneTool 不保存密码。
- 清除当前服务端的旧网络连接或旧 Windows 凭据，用于处理同一服务端多账号冲突。
- 打开凭据管理器，作为高级入口。
- 打开打印机设置。
- 打开 `\\服务端`，方便验证共享是否可见。

## 后端设计

扩展 `TroubleshootingService`：

- `diagnosePrinterShare(input)`：本地 PowerShell 采集诊断事实，TypeScript 归一化并生成结论。
- `repairPrinterShare(input)`：按动作执行本机修复。需要管理员权限的动作通过提升的 PowerShell 包装执行。
- `openPrinterShareTarget(input)`：打开凭据管理器、打印机设置或服务端 UNC。

PowerShell 与 TypeScript 分工：

- PowerShell 只采集事实或执行明确动作。
- TypeScript 负责风险判断、推荐动作、用户可读文案。
- 所有输入先规范化并拒绝危险字符，避免把 UNC/主机名拼进命令造成注入。

## 前端设计

在现有“疑难修复”页中新增第二张卡片“打印共享修复”：

- 默认只显示服务端地址、可选共享打印机名和“开始修复”主按钮。
- 检测后显示当前结论和唯一下一步动作。
- 凭据表单只在向导判断需要凭据时出现，密码输入后立即交给 Windows 凭据管理器。
- 危险动作使用确认弹窗。
- “高级诊断”折叠区展示链路检查项、旧连接、已保存凭据目标和服务端检查思路，避免普通用户被信息淹没。

## 安全与风险

- 清空队列只移动或删除本机 spool 队列文件，不碰驱动和打印机对象。
- RPC 兼容修复会写入：
  - `HKLM\SOFTWARE\Policies\Microsoft\Windows NT\Printers\RPC\RpcUseNamedPipeProtocol=1`
  - `HKLM\SYSTEM\CurrentControlSet\Control\Print\RpcAuthnLevelPrivacyEnabled=0`
- 上述兼容项只在用户确认后执行，并在 UI 中说明用于旧服务端/旧共享环境。
- SMB 1.0 第一版不自动开启，只提示风险和入口。

## 测试

- 共享模型测试：不同诊断事实能归类为客户端、服务端、协议兼容、未知。
- 服务测试：非 Windows 环境返回不支持；Windows 诊断能解析标记 JSON；修复脚本包含预期服务/注册表操作。
- IPC/预加载测试：新增诊断、修复、打开入口通道。
- 页面源测试：打印共享卡片、客户端诊断文案、风险确认和 API 调用存在。
- 类型检查和全量测试通过后，再用预览确认入口和页面内容出现。
