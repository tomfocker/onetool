# OneTool v0.3.2 Release Design

## Goal

Ship `v0.3.2` as a low-risk Windows patch release focused on the Proxy Doctor work already completed on `codex/proxy-doctor-integration`.

The release should not introduce another large feature. It should make the version metadata, README, release notes, verification status, tag, and GitHub release path line up cleanly.

## Current Context

The project version is currently `0.3.1` in `package.json` and `package-lock.json`, while `README.md` still describes `v0.3.0` and its artifact names. The latest branch commits add and polish Proxy Doctor:

- compact status lamps for proxy layers
- proxy target probing with clearer timeout guidance
- current-value testing for mismatched proxy layers
- a proxy launcher that starts selected `.exe` or `.com` apps with injected proxy environment variables
- layout fixes so table actions stay visible in normal desktop windows

The repository already has a Windows release workflow in `.github/workflows/release.yml`. Tag pushes matching `v*` run tests, package Windows artifacts, upload them, and create a draft GitHub Release.

## Release Scope

This release includes:

- bump package metadata from `0.3.1` to `0.3.2`
- update README version badge, version copy, artifact names, and current-version positioning
- add `docs/distribution/release-notes-v0.3.2.md`
- update `docs/distribution/windows-release.md` examples from the stale `v0.3.0` wording to a current `v0.3.2` example
- run the standard verification chain before tagging
- push the branch and create/push tag `v0.3.2`

This release does not include:

- forced per-app proxying through TUN, WinDivert, or packet interception
- broader UI redesign outside the release-facing text
- code signing changes
- macOS or Linux release promises

## Versioning

Use `0.3.2` because the work is additive and patch-level relative to the already published `0.3.x` Windows line. It improves one tool area and release documentation without changing the app architecture or compatibility contract.

Expected artifact names after packaging:

- `onetool-0.3.2-win-x64-setup.exe`
- `onetool-0.3.2-win-x64-portable.exe`
- `latest.yml`
- matching `.blockmap` files

## Release Notes

The `v0.3.2` notes should lead with Proxy Doctor improvements:

- status lamp overview for Windows, WinHTTP, environment variables, Git, npm, current process, and Codex process
- target proxy testing that separates raw port reachability from actual proxy request success
- clearer guidance for endpoints such as `100.64.0.6:20172` that may be upstream nodes rather than direct system proxy endpoints
- proxy launcher for starting a selected program with proxy environment variables
- layout cleanup so diagnostics and actions fit better in the OneTool window

The notes should include the known limitation that the launcher only affects newly started processes that honor proxy environment variables.

## Verification

Before tagging:

- `npm test`
- `npm run typecheck`
- `npm run build`

If local packaging permissions allow it, also run:

- `npm run release:win`

If local Windows packaging is blocked by symlink or `winCodeSign` permissions, use the tag-triggered GitHub Actions release workflow as the authoritative package producer.

## GitHub Release Flow

After verification and commit:

1. Push `codex/proxy-doctor-integration`.
2. Create annotated tag `v0.3.2`.
3. Push `v0.3.2`.
4. Wait for the GitHub Actions Release workflow to create the draft release.
5. Review draft assets and notes before publishing the release.

## Risks

The main release risk is user expectation around the proxy launcher. The UI and release notes must state that it injects environment variables into newly launched processes, not that it can force every app through a proxy.

The second risk is stale documentation. README, release notes, and release guide examples must use the same `v0.3.2` wording so users do not download or look for `v0.3.0` artifact names.
